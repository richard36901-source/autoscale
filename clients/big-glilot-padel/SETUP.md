# פאדל BIG גלילות — הקמה ב־10 דקות

עלות הפעלה: **0 ₪**. אין Make, אין שרת, אין מסד נתונים בתשלום.
הדף הוא קובץ סטטי ב־GitHub Pages, והגיליון עצמו הוא הבסיס נתונים.

---

## 1. גיליון + סקריפט (7 דקות)

1. פתחו גיליון Google חדש. קראו לו למשל **פאדל גלילות**.
2. תפריט **Extensions → Apps Script**.
3. מחקו את מה שיש שם, הדביקו את כל התוכן של `Code.gs`, ושמרו.
4. בחרו למעלה את הפונקציה **initCodes** ולחצו **Run** — זה שומר את קוד הכניסה
   לעובדים (6801) ואת קוד המנהל (3072) ב־Script Properties, לא בקובץ עצמו.
5. בחרו את הפונקציה **setup** ולחצו **Run**.
   - בפעם הראשונה גוגל תבקש אישור הרשאות — אשרו (Advanced → Go to project).
   - זה יוצר את כל הלשוניות (יומן רישום, השבוע, שבועות קודמים, מובילים,
     ביטולים, עובדים מורשים), זורע את רשימת העובדים המורשים, פותח את
     משבצות השבוע הפעיל, ומתזמן שני טריגרים אוטומטיים.
6. **Deploy → New deployment → Web app**:
   - `Execute as`: **Me**
   - `Who has access`: **Anyone**
   - לחצו Deploy והעתיקו את ה־**Web app URL**.

## 2. הדף (3 דקות)

1. פתחו את `index.html`, בראש ה־`<script>`:
   ```js
   const API = "PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE";
   ```
   הדביקו שם את הכתובת מסעיף 1.6.
2. העלו את התיקייה לריפו של GitHub Pages תחת `big-glilot-padel/`.
3. הכתובת שתצא: `https://<הדומיין-שלך>/big-glilot-padel/`

זהו. שולחים את הקישור לקבוצה, יחד עם קוד הכניסה (6801).

## איך זה בנוי

**4 משחקים בשבוע**, לא מגרש אחד. יום ושעה קבועים כל שבוע, 4 שחקנים לכל משחק —
16 מקומות בסך הכל. ההרשמה לכל ארבעת המשחקים נפתחת יחד, פעם בשבוע, ביום ובשעה
קבועים (כרגע: יום ראשון 12:00 — ראו `OPENS` ב־`Code.gs`).

| מתי | מה קורה |
|---|---|
| ביום וברגע שההרשמה נפתחת | כל 16 המקומות של השבוע נפתחים יחד. |
| עובד תופס מקום | חייב לבחור שם מתוך רשימת העובדים המורשים (לא להקליד חופשי) ולהזין טלפון. נרשמת שורה עם השם, הטלפון וקוד ביטול אישי. |
| שני עובדים לוחצים יחד על אותו מקום | `LockService` נועל. אחד מקבל, השני רואה "מישהו הקדים אותך". |
| משחק מתחיל | נסגר להרשמה 2 דקות אחרי תחילתו (`RESET_AFTER`). |
| שחרור מקום | רק מהמכשיר שנרשם, או עם מספר הטלפון שאיתו נתפס המקום, או עם קוד המנהל. הביטול נשמר בהיסטוריה. |

המעבר בין שבועות קורה מעצמו בכל טעינה של הדף, כך שגם אם הטריגר השבועי ייפול,
המקומות ייפתחו.

## מי מותר להירשם — רשימה סגורה

לשונית **"עובדים מורשים"** בגיליון (עמודה A שם, עמודה B טלפון) היא רשימת
ה־whitelist. בדף, מקלידים אות אחת מהשם ובוחרים מתוך הרשימה שמסתננת — אי אפשר
להקליד שם חופשי, וגם השרת בודק שהשם קיים ברשימה לפני שהוא מקבל הרשמה.

**להוסיף או להסיר עובד**: מוסיפים/מוחקים שורה בעמודה A של הלשונית הזאת.
השינוי חי בשרת מיד; ברשימה שמוצגת בדף יש מטמון של עד 5 דקות.

**נעילת טלפון**: בפעם הראשונה שמישהו נרשם בשם מסוים, הטלפון שהוא הקליד ננעל
לשם הזה בעמודה B. מאותו רגע, רק אותו טלפון יכול להירשם תחת השם הזה. **לשנות
טלפון נעול**: מוחקים את התא בעמודה B ליד השם — בפעם הבאה שהוא יירשם, הטלפון
החדש ייעל מחדש.

## איך מובטח שרק מי שתפס יכול לשחרר

שלוש דרכים:

1. **אותו מכשיר.** ברגע ההרשמה נוצר קוד אישי שנשמר בדפדפן של העובד. מי שפותח
   את הדף מאותו מכשיר רואה את המקום שלו מסומן ואת כפתור הביטול.
2. **מכשיר אחר.** לוחצים על השורה ומקלידים את מספר הטלפון שאיתו נתפס המקום.
   השרת משווה, ורק אם זה אותו מספר המקום משתחרר.
3. **קוד מנהל.** מקלידים את קוד המנהל (3072) בשדה הטלפון — זה משחרר כל מקום,
   של כל אחד. שמור למי שמנהל בפועל את המועדון.

## לשנות את הימים והשעות של המשחקים

יש **נקודת עריכה אחת בלבד לכל קובץ**, ושתיהן חייבות להישאר זהות:

**`Code.gs`**, למעלה:
```js
var GAMES = [
  {day: 'שלישי', start: '17:00', end: '18:00'},
  {day: 'שלישי', start: '18:00', end: '19:00'},
  {day: 'חמישי', start: '17:00', end: '18:00'},
  {day: 'חמישי', start: '18:00', end: '19:00'}
];
```

**`index.html`**, בראש ה־`<script>` — אותו מערך, בדיוק באותו סדר:
```js
const GAMES = [
  {day: "שלישי", start: "17:00", end: "18:00"},
  {day: "שלישי", start: "18:00", end: "19:00"},
  {day: "חמישי", start: "17:00", end: "18:00"},
  {day: "חמישי", start: "18:00", end: "19:00"}
];
```

שינוי הימים/השעות משפיע רק על שבועות **חדשים** שנפתחים מרגע השינוי והלאה —
משבצות שכבר נוצרו בגיליון לשבוע הפעיל נשארות עם היום/השעה שהיו כשהן נוצרו,
כולל הרשמות קיימות. הכותרות בדף (הבאנר האדום למעלה וכותרת כל כרטיס משחק) כן
מתעדכנות מיד, כי הן נגזרות מ־`GAMES` בזמן אמת.

אחרי שינוי כזה חובה: להדביק שוב את `Code.gs` **ולפרוס גרסה חדשה** —
Deploy → Manage deployments → עיפרון עריכה → Version: New version → Deploy.
זו אותה כתובת בדיוק, רק שהיא צריכה גרסה חדשה כדי להריץ את הקוד המעודכן —
Save לבד בעורך לא מספיק.

## לשנות את האדום למותג האמיתי

ב־`index.html`, בראש ה־CSS:
```css
--ink:#E4002B;
```
זה האדום העיקרי בקובץ (יש עוד גרסה כהה למצב הלילה, `--ink:#EC002C`, באותו
מקום בערך). מחליפים ואת הריבוע `BIG` בלוגו האמיתי — וזהו.

## מה לא כלול (וזה בכוונה)

שליחת ההודעות בוואטסאפ. כרגע מי שמנהל את המועדון מדביק את הקישור בקבוצה
ידנית, ואת התזכורת ביום המשחק שולח ידנית. זו נקודת ההרחבה בתשלום:
שליחה אוטומטית לקבוצה, תזכורת ביום המשחק לכל זוכה, והודעת
"נפתחה משבצת" אוטומטית כשמישהו מבטל.

## שני דברים שכדאי לדעת

**מצב תצוגה.** כל עוד לא הדבקתם כתובת Apps Script (`API` מתחיל ב־`PASTE_`),
הדף עובד עם נתוני דוגמה ואפשר ללחוץ ולעבור על כל המסכים, כולל רשימת שמות
דמו לבחירה. נוח להראות ללקוח לפני שמחברים גיליון.

**הדף זוכר את העובד.** אחרי הרשמה, הדפדפן שומר את קוד הביטול. מי שיפתח שוב
את אותו קישור יראה את המקום שלו מסומן, עם כפתור ביטול, בלי להתחבר לשום דבר.

**אזהרת אבטחה.** לעולם לא להעלות את `Code.gs` לריפו הציבורי (GitHub Pages) —
רק את `index.html`, `og.png` ו־`ics/`. הקודים (6801, 3072) שמורים ב־Script
Properties בדיוק כדי שלא יהיו נגישים משם, אבל הקובץ עצמו עדיין לא אמור
להתפרסם.
