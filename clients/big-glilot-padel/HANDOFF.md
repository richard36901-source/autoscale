## איפה משנים דברים

**לוח המשחקים** — צריך לשנות בשני מקומות, לאותם ערכים:

`Code.gs` בראש הקובץ:
```javascript
var GAMES = [
  {day: 'שלישי', start: '17:00', end: '18:00'},
  {day: 'שלישי', start: '18:00', end: '19:00'},
  {day: 'חמישי', start: '17:00', end: '18:00'},
  {day: 'חמישי', start: '18:00', end: '19:00'}
];
var OPENS = { day: 'ראשון', time: '12:00' };
var SPOTS = 4;
var ONE_PER = 'game';     // 'week' = מקום אחד בשבוע כולו
var RESET_AFTER = 2;      // דקות אחרי תחילת משחק שבהן הוא נסגר
```

`index.html` בראש ה-`<script>`: אותו `GAMES` ואותו `OPENS`.

**חשוב:** אם משנים את לוח המשחקים, צריך גם לייצר מחדש את קבצי היומן
ב-`ics/` (ראו "תחזוקה").

**פתיחה חד-פעמית** — `FORCE_OPEN_UNTIL` ב-`Code.gs`. עד המועד שכתוב שם
ההרשמה פתוחה בלי קשר ליום ראשון. אחריו המערכת חוזרת לבד לכלל הרגיל.
להשאיר `''` כדי לבטל.

**הצבע** — `--ink` בראש ה-CSS ב-`index.html`. זה האדום היחיד בקובץ.

## פריסה של שינוי ב-Code.gs

1. הגיליון → Extensions → Apps Script
2. **בחר הכל** (Cmd+A) → מחק → הדבק את הקובץ החדש → שמור
3. **Deploy → Manage deployments → ✏️ → Version: New version → Deploy**
4. להעתיק את ה-Web app URL ולהדביק ב-`index.html` במשתנה `API`
5. לדחוף את `index.html` ל-GitHub

**שלב 3 הוא הקריטי.** בלי גרסה חדשה הכתובת ממשיכה להריץ את הקוד הישן,
כמה פעמים שלא תדביק אותו.

פונקציות שמריצים ידנית מהבורר בעורך:
- `setup` — יוצר את הלשוניות והטריגרים. פעם אחת אחרי פריסה.
- `initCodes` — שומר את שני הקודים. פעם אחת.
- `resetAll` — **מוחק הכל**, כולל היסטוריה. רק לפני עלייה לאוויר אמיתית.
- `resetThisWeek` — מנקה רק את השבוע הנוכחי.
- `refreshViews` — בונה מחדש את הלשוניות עכשיו.
- `dedupe` — מוחק שורות כפולות אם נוצרו.
- `showCodes` — מציג את הקודים השמורים.

## תחזוקה

**קבצי היומן נגמרים במרץ 2027.** יש 121 קבצים ב-`ics/`, ארבעה משחקים
× 30 שבועות, ועוד `open.ics` לתזכורת ההרשמה. כשהם נגמרים צריך לייצר
עוד ולהעלות. הסקריפט שמייצר אותם נמצא בהיסטוריית השיחה; הנקודות
הקריטיות: קידוד UTF-8, שורות מסתיימות ב-CRLF, וקיפול שורות ל-75 בתים
לפי RFC 5545 עם חיתוך על גבול תו שלם.

**אם משנים ימים או שעות** — צריך לייצר את כל הקבצים מחדש.

## מה שחשוב לדעת ולא מובן מאליו

**היומן מתנהג שונה בין דפדפנים, וזה לא באג.** ספארי פותח `text/calendar`
ומציג את חלון היומן. כרום תמיד מוריד קבצים כאלה, בכל אתר, ואי אפשר
לשנות את זה מהדף. לכן כרום מקבל קישור ליומן גוגל עם האירוע ממולא.
כל ניסיון "לאחד" את שני המסלולים שבר את אחד מהם.

**Apps Script איטי מטבעו.** הרצפה היא כ-1.5 שניות לבקשה, ואי אפשר לרדת
מתחתיה. הדף מפצה: מצייר מיד את המצב השמור, מושך את הלוח מראש, ומחמם
את השרת ברגע הטעינה. אם המהירות תהפוך לבעיה אמיתית — המעבר ל-Cloudflare
Worker עם D1 ייתן 50-100 מילישניות, גם הוא בחינם.

**אף פעם לא להריץ עבודה כבדה בתוך בקשה.** בנייה של ארבע לשוניות בתוך
קריאת רשימה העלתה את זמן התגובה ל-55 שניות. זו הייתה התקלה הגדולה
ביותר בפרויקט.

**המטמון:** תשובת הרשימה נשמרת 15 שניות בשרת. כל כתיבה מנקה אותו מיד,
אז אף אחד לא רואה מקום שכבר נתפס.

## מה שנבדק, ומה שלא

**נבדק בהרצה מול השרת האמיתי:** קוד שגוי נדחה, תפיסה נשמרת, כפילות
באותו משחק נחסמת, משחק אחר מותר, שם חלקי נדחה, מקום תפוס לא נתפס שוב,
מספר זר לא מבטל, המספר הנכון מבטל, קוד מנהל משחרר, ושתי בקשות במקביל
לאותו מקום — אחת מקבלת והשנייה מקבלת `taken`.

**נבדק בדפדפן על הדף החי:** שער הקוד, הרשימה, הטופס, תפיסה שנשמרה
בגיליון, כפתור היומן שמופיע רק אחרי אישור, סימון המקום וביטולו,
מצב כהה, ואפס שגיאות בקונסול.

**נבדק בהרצה מבודדת:** לוח הזמנים לאורך שבועות, חסימת כפילות בכל
פורמט טלפון, וקישורי היומן על חמש זהויות דפדפן.

**לא נבדק:** פתיחת היומן על אייפון פיזי (אין גישה למכשיר), 16 אנשים
אמיתיים בו-זמנית (רק שתי בקשות מקבילות), והתנהגות אחרי מעבר שעון קיץ.
